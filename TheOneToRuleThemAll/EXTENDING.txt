THE ONE TO RULE THEM ALL — CLASS MODULE CONTRACT

Core.lua owns profile registration, preview, compatibility checks, native
macro creation, transactional action placement, and per-character undo.

To add a module, load its Lua file after Core.lua in the .toc and call
TheOneToRuleThemAll.RegisterProfile with:

id, class (WoW class token), spec (numeric specialization ID), specName, label, optional requiredPage and blockedWhileStealthed, evidence {patch, gear, tuning, validation},
layouts {standard={description}, compact={description, altSlots={...}}},
build(api, layout, enforce) -> {rows, macros, skipped, lines}.

Each row is: 
{slot=<action-slot number>, action=<spell or macro record>}.

Spell records use api.spell(id); macros use api.macro(name, body). 

Every macro referenced by a row must also occur in plan.macros. 

Optional spells:
must be checked with api.learned; profile compatibility checks run when
enforce=true. 

Preview must not write game state. 

Macro bodies are localized
through api.spellName and checked against native name/body limits.

UI.lua = lazy setup panel. 

A.Inspect returns read-only readiness and preview; 
A.Execute is the single guarded command path used by slash and panel actions.

The panel's events refresh presentation only while the panel is visible.

All write occur on explicit out-of-combat setup/undo command or click. 

Modules must not add combat-event decision logic, timer-driven rotation selection, gear
changes, talent purchases, keybinding writes, or automatic profile switches.

Don't infer class's bars, forms, hero replacements, spell overrides from modules. 

A new class need its own placement + undo test.

STANDARD

Use Method.gg's latest verified Mythic+ builds with exact imports and sources.
Custom builds and simulations are outside the addon's development scope.
